html-diagram 스킬로 포스터 한 장을 만드는 모델 비교 실험입니다. 아래 규칙을 정확히 지키세요.
1. <skill-dir>/SKILL.md 를 읽고 그 워크플로를 따릅니다. 스킬 폴더(<skills-dir>/) 안의 파일은 절대 수정하지 않습니다(읽기만).
2. 비교 실험 오염 방지: examples/poster-src.html 과 examples/poster.html 은 같은 주제의 기존 산출물이므로 열어보지 마세요. 다른 예시(demo-src.html, drug-pipeline-src.html)는 참고해도 됩니다.
3. 주제: "편집 가능한 도식 엔진 기능 샘플러" 포스터. 이 엔진이 제공하는 모든 노드 종류(카드, 원형, 투명, 반투명, 그림자 등), 화살표 속성 전부(실선/파선/점선, 화살촉 end/both/none, 곡률, 투명도, 흐름 애니메이션, 측면 앵커, 비율 앵커, 좌표 끝점, 라벨), 텍스트 서식(제목, 굵게, 기울임, 밑줄, 취소선, 글자색, 배경 강조, 목록, 인용, 표, 정렬, 크기 단계), 편집 조작(단축키)과 저장 흐름을 한 장에서 보여 주고, 각 요소가 스스로를 설명하게 합니다. 캔버스는 2개 이상(여러 캔버스 기능 시연). 한국어. 스킬 규칙대로 이모지 금지, 줄표 금지. 전문 디자이너 수준의 인포그래픽을 목표로 합니다.
4. 산출 경로: 현재 작업 폴더의 poster.html. 작업 파일도 이 폴더 안에만 만드세요.
5. 검증: 브라우저 도구가 없으므로 정적 검사로 대신합니다. 검사 스크립트를 만들어 실행하고 결과를 보고하세요: (a) 모든 .fig-node에 유일 id와 인라인 left/top/width (b) 모든 .fig-edge의 data-from/data-to가 실존 노드 id 또는 "x,y" (c) 줄표(em dash, en dash) 0개 (d) <title> 교체됨 (e) 엔진 블록(두 번째 <style>과 마지막 <script>)이 assets/template.html의 것과 바이트 동일 (f) 캔버스 안 글자 크기 12px 미만 없음, 본문 13px 이상 (g) data-size가 콘텐츠 범위와 정합. 서버·브라우저 검증은 하지 않아도 됩니다(별도 하네스가 수행).
6. 마지막 메시지에 이 구조로 보고: (1) 산출 파일 경로와 크기 (2) 노드 수, 엣지 수, 캔버스 수 (3) 정적 검사 결과 (4) 사용한 화살표 속성과 노드 종류 목록 (5) 어려웠던 점.
